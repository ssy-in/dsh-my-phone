| v1.8.30 | **技术动态不再漏数据，也不再混淆「等授权」**：①**根因是共用环形缓冲** —— `src/gate.js` 只有 `events` 一个 40 条的环（`if (events.length > 40) events.shift()`），`turnok`/`longrun` 这种高频人工事件几分钟就把名额吃满；实测活动实例 40 条里 19 条 `turnok` + 10 条 `longrun`，真正的技术动态（扫描 401、上游 503）全被挤掉，用户截图上技术动态只剩两条，问「这里漏数据了吧」。现在技术类单独存第二条环 `techEvents`（上限 60），`buildFeed()` 的 `tech`/`techRaw` 改读它，两条环互不挤占；`clearLogs()` 一并清；②**「会话在等授权」不该出现在技术动态里** —— `approval` 不在 `HUMAN_KINDS` 里，于是被当成技术噪音；新增 `QUIET_KINDS = new Set(['approval'])`，这类只留排查日志，既不进「技术动态」也不进「消息」（`pending` 里已经有一张带 id 的授权卡了，再列一次是重复），`HUMAN_KINDS`/`WARN_KINDS`/`QUIET_KINDS` 一并上移到 `note()` 之前；③**手机端还是读不到技术动态** —— `bubbleCandidates()` 的 tech 段与兜底段、`bubbleCard()`、`summary()`、`logRows()` 全部写死 `data`（手机端恒为 null，快照在 `remote`），统一改成 `var src = data \|\| remote` |
| v1.8.29 | **NEW 与红点终于能清掉了（三处独立的坑一起修）**：①**宿主事件字段读错层** —— `session/event` 回调拿到的是 `{ seq, type, data }`，所有业务字段都在 `event.data` 下，插件却一直读顶层：于是 `approval/asked` 的 `id` 永远是空串（`decideApproval` 首行 `if (!id) return null` → 那行「等授权」永远删不掉）、`toolName` 空（没有「正在用 Read」）、`turn/end` 的 `reason` 空（失败被当正常完成）、`plan/mode` 的 `active` 是 undefined（计划模式永远判成 agent）。现在统一走 `const ev = event.data \|\| event` + `evf(k)`（顶层兜底）；②**`approval/decided` 匹配不上合并行** —— 8 秒合并窗里的新 `approvalId` 原来直接覆盖 `last.id`，后到的 decided 若是更早那个 id 就失效，现在每行记 `ids` 数组，命中任意一个就算答掉；③**手机端已读走错门** —— `markFeedSeen()` 只会 `post('read')` 打 `/__myphone/panel/read`，那头 `if (!isLoopback(req)) return 404`，手机必然 404，于是 NEW 与红点在手机上永远不消失。现在远端模式改打公网口的 `/__myphone/ack`（带 `x-myphone-phone: 1`，服务端新增 `body.read` → `markNoticesRead()` 并回新的 `pendingCount`/`unread`）；④**关面板不落已读** —— 用户正常路径是「点开 → 进消息/日志 → 看完点 × 关掉」，全程没「离开读页」，那条 `markFeedSeen()` 一次都没触发过 → `close()` 里补上（tab 是消息/日志或高级时）；⑤**手机端认 `remote` 快照** —— `feedItems()` / `techRows()` / `unreadCount()` 原来只认 `data`（手机端恒为 null），所以手机红点恒 0、消息页只能糊一遍 `remote.events` 原始日志；现在统一 `var src = data \|\| remote`，手机端也是同一套信笺卡片（事件标签、NEW、倒序），`loadRemote()` 成功后补 `paint()` 刷红点；⑥消息页文案改「离开这一页或关掉面板时记已读」（原来写「离开这一页」，与实际行为不符） |
| v1.8.28 | **朝左的气泡不再压住悬浮球 + 红点变小并若隐若现**：①`placeBubble()` 里左侧那支把气泡的**右边缘**放在了球心上（`left = cx - gap - w`，而右侧那支用的是 `r.left + r.width + gap` 这种边缘算法），结果一半压在球上；现在统一按球的外边缘算（`left = r.left - gap - w`），放不下就翻到右侧，右侧算法没动；②红点 `24px` → `17px`（字号 13→10.5、内距 7→5、偏移 -4→-3），动效从「向外扩散的 box-shadow 脉冲」（看着像在闪）换成整颗球的透明度呼吸 `dmp-breathe`（2.6 秒一轮，1 → 0.42），并给 `prefers-reduced-motion` 关掉动画 |
| v1.8.27 | **消息列表不再跳回第一行 + 手机上少跑一趟空请求**：①`render()` 每次都是「清空 `body` → 重新 append」，新节点的 `scrollTop` 天然是 0，于是往下翻着看消息时，一来新消息（或 SSE 推一帧）就弹回第一行。现在重画前后按「容器 + 序号」保存/恢复滚动位置（`snapshotScroll()` / `restoreScroll()`，覆盖 `body` 自身与 `.feed`、`.dmp-logbox` 三类滚动区）；②手机上 `/__myphone/panel` 必然 404（管理口只给回环地址），原来每 6 秒都要先撞一次 404 再转 `/__myphone/state`，白跑一趟。现在记住 `remoteMode` 直接打只读口，每轮省一次往返，并且每 60 秒回探一次管理口（桌面端偶发失败不会永久卡在只读模式） |
